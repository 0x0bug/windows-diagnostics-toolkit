# Windows Diagnostics Toolkit v0.2.0-beta.1

This prerelease adds structured snapshots, offline comparison, and incident
investigation to the existing local Windows diagnostics. It supports Windows
PowerShell 5.1 and PowerShell 7 without third-party runtime dependencies.

## Added

- Opt-in `-SaveSnapshot` JSON for explicitly selected System, Crashes, Events,
  and Updates modules. Schema version 1 stores normalized diagnostic data,
  source coverage, and execution status independently of human-readable output.
- Offline comparison through `-BeforeSnapshot` and `-AfterSnapshot`. Comparison
  reads the two JSON files without querying Windows, preserves the inputs, and
  writes TXT with optional Markdown. Results distinguish comparable changes,
  windowed observations, information gained or lost, and identities that cannot
  be compared across captures.
- Incident reports for `-IncidentSymptom AppFailure` and `UnexpectedRestart`
  with `-IncidentAt` and optional before/after bounds. Reports use an explicit
  UTC window, link observations to source evidence, retain ambiguous records,
  and show source availability and timing limitations. The default window is
  30 minutes on each side of the supplied time; an explicit offset or `Z` is
  required. TXT and optional Markdown are supported.

## Fixed

- Hardened child-process execution, timeout handling, stream capture, and
  PowerShell quoting for paths and arguments, including typographic apostrophes.
  Progress records are suppressed, and informational, warning, and error streams
  remain readable text instead of raw CLIXML in Windows PowerShell 5.1.
- Checked output-folder create, write, and delete access before live collection,
  using an owned temporary probe without overwriting an existing file.
- Improved Privacy Mode for email addresses, DNS and proxy configuration,
  identifiers, and known host/user identities in event narratives. Recognizable
  application, process, and dump-file names remain useful diagnostic context.
  More credential-option variants are redacted even without Privacy Mode.
- Kept successful empty queries, unavailable sources, collection failure, and
  diagnostic findings distinct. Storage now emits explicit availability warnings
  when both primary and fallback data sources return no usable inventory.
- Added bounded bootstrap download requests while preserving fixed-release
  URLs, SHA-256 verification before extraction, caller scope, and cleanup on
  failure. The bootstrap is pinned to `v0.2.0-beta.1`.
- Expanded regression coverage for privacy, source availability, snapshots,
  incident evidence, process cleanup, output paths, and release packaging.

## Limits and compatibility

This remains a beta. Ordinary CLI selectors, standalone compatibility scripts,
and TUI defaults are retained; snapshots and incident investigation are explicit
CLI workflows. The persisted JSON schema remains version 1.

Missing data is not proof of a healthy system. Source limits, retention, moving
windows, and collection failures constrain conclusions. Event 41 does not prove
a restart cause; update failures do not prove successful installation, and
temporal ordering does not establish causality. Snapshots do not verify that two
captures came from the same PC, and per-capture privacy tokens are not stable
cross-capture identities. Get-HotFix is a limited current inventory.

Privacy Mode cannot recognize every sensitive phrase in application-provided
event messages. Review generated artifacts before sharing them; ambiguous
extensionless names may be redacted conservatively. No automatic remediation,
telemetry, or report upload was added.
